# 그곳잡

현장 근로자와 고용주를 연결하는 채용 서비스 프로토타입입니다. 바닐라 HTML/CSS/JavaScript와 Vite를 사용하며, Supabase 데이터베이스와 Vercel 배포를 기준으로 구성했습니다.

## 포함된 기능

- 고용주·근로자별 시작 화면
- 조건 입력, 추천 근거, 면접 제안, 채용 결정 프로토타입
- 실제 실적과 분리된 시연용 가상 인재
- 근로자 업무정보 본인 조회와 고용주용 시연 화면
- 점수를 계산하지 않는 조건 비교와 AI 개발 예정 안내
- 단기 비자 지원·현금 인출 가능한 플랫폼 포인트 검토 예정 안내
- 모바일 반응형 UI, 오프라인 셸 캐시, 홈 화면 설치(PWA)
- 이메일·비밀번호 회원가입/로그인과 자동 회원 프로필 생성
- 면접·상담·첫 출근 예약 등록, 조회, 취소
- Supabase Auth/RLS 기반 사용자별 데이터 보호

## 로컬 실행

Node.js 22 이상이 필요합니다.

```bash
npm install
copy .env.example .env
npm run dev
```

`.env`에 Supabase 프로젝트의 URL과 **publishable key**를 설정하세요. 설정하지 않으면 회원/예약 영역에 설정 안내가 표시됩니다. 브라우저 코드에는 secret/service role 키를 절대 넣지 마세요.

## Supabase 설정

1. Supabase 프로젝트를 생성합니다.
2. `supabase/migrations`의 SQL을 Dashboard SQL Editor 또는 Supabase CLI로 적용합니다.
3. Authentication > Providers > Email에서 이메일 제공자가 활성화되어 있는지 확인합니다. 이메일 확인을 사용하는 운영 환경에서는 Site URL과 Redirect URL도 설정합니다.
4. 회원가입 시 근로자/고용주 유형을 선택하면 `profiles` 행이 자동 생성됩니다. `admin` 역할은 클라이언트에서 설정할 수 없습니다.
5. AI 모델/추천 계산 엔진은 현재 연결되어 있지 않습니다. 클라이언트에는 publishable key만 제공합니다.

마이그레이션은 모든 공개 테이블에 RLS를 적용합니다. 회원은 자신의 프로필과 예약만 관리할 수 있고, 프로필의 역할 변경과 포인트 원장 생성은 일반 클라이언트에서 허용하지 않습니다. 포인트 적립·환산·출금 기준은 미정이며, 출금 클라이언트 함수는 항상 거절합니다. 관련 테이블의 존재는 실제 운영을 뜻하지 않습니다.

## 직업정보제공 MVP

개발 환경에서만 아래 값을 추가해 MVP 화면을 활성화합니다.

```text
VITE_JOB_INFO_MVP_MODE=development
```

- 고용주 정보, 구인 공고, 실제 근무조건 등록·조회
- 근로자 정보 등록, 공고 조회, 직접 지원 및 지원 후 직접 연락
- 고객 요구와 서비스 이용 의향 기록
- 개인정보 동의 이력 저장(현재 문안 버전은 법률 검토 전 초안)

프로덕션에서는 위 값을 설정하지 않거나 `disabled`로 유지합니다. DB의 운영 설정도 기본값이
`false`이며 신고 확인 일시가 없으면 활성화할 수 없습니다. 실제 운영 전에는 직업정보제공사업
신고 완료 확인과 개인정보 동의·처리방침·이용약관 법률 검토가 필요합니다. 운영자에 의한
구직자 소개와 고객 결제는 이 MVP에서 활성화하지 않습니다.

## 시제품 1 클로즈 베타

관리자 계정의 개발 환경에서만 아래 값을 추가해 수동 소개 콘솔을 활성화합니다.

```text
VITE_CLOSED_BETA_MODE=development
```

- 제한 참여자 지정과 실제 근무조건·근로자 경험·희망조건·통근 여건 수동 비교
- 고용주 의견, 운영자 선택 근거와 소개 내역 기록
- 근로계약 체결 확인 상태 및 운영자가 입력한 확인 방법·근거 기록
- 테스트 결제수단·동의 기록 후 계약 확인이 된 경우에만 무청구 결제 흐름 완료 가능
- 출근 여부, 첫 근무 완료 여부와 계약기간 결과 기록

19,000원은 `temporary_validation`으로 표시되는 임시 검증 가격이며 정식 수수료나 가입비가
아닙니다. 결제 제공자는 연결하지 않았고 실제 카드 정보나 실제 청구를 처리하지 않습니다.
유료직업소개사업 등록 확인 상태는 기본값이 잠금이며 임의로 완료하지 않습니다. 계약 확인
방법과 계약기간 이행률 계산 기준도 아직 확정되지 않아 확인 근거는 자유 입력으로 기록하고
이행률 수치는 계산하지 않습니다.

## 프로토타입 데이터 구분

- 회원가입·로그인과 예약 등록·조회·취소는 Supabase에 실제 저장됩니다.
- 직업정보 MVP는 신고 확인 전 개발 모드에서만 저장·조회됩니다.
- 조건 입력 → 추천 근거 → 면접 제안 → 채용 결정 화면은 저장되지 않는 시연입니다.
- 가상 인재는 실제 기록과 별도로 관리하고 `시연용 가상 데이터`로 표시합니다.
  2026-09-16부터 공개 화면의 근거 없는 추천·성실성 점수와 가상 통근 거리 수치는 제거했습니다.
- AI 추천 계산 엔진과 비자 지원 접수는 아직 실제 기능으로 연결되지 않았습니다.

## 시제품 2 오픈 베타

관리자 또는 참여 회원의 개발 환경에서만 아래 값을 추가해 실제 기록 화면을 활성화합니다.

```text
VITE_OPEN_BETA_MODE=development
```

- 사업장·근로자 좌표와 관리자가 확정한 계산 방식·근거리 기준이 모두 있을 때만 거리 판별
- 근무 종료 결과(`completed` 또는 `ended_early`)가 기록된 뒤 근로자의 급여 지급 여부 응답 저장
- 근로자 응답과 운영자의 미지급 확정 검토를 분리하고, 확정 정책 버전 없이는 확정 불가
- 확정 미지급 검토와 이용 제한 정책 버전·결정 근거가 모두 있어야만 고용주 제한 가능
- 고용주 의견과 실제 근무 결과에서 확인한 매칭 기준 관찰 기록
- 실제 수수료 결제, 재이용 응답, 실제 운영비용을 각각 별도 기록하고 실제 행만 집계

현재 근거리 기준·거리 계산 방식, 미지급 확정 기준, 고용주 이용 제한 정책이 확정되지 않아
DB 설정값은 비어 있습니다. 결제 제공자와 서버 웹훅도 연결되지 않았고 사업 등록 확인 상태가
잠겨 있으므로 수수료 `paid` 완료 기록은 거부됩니다. 데이터가 없는 성과 항목은 `미집계`로
표시하며 예시값으로 채우지 않습니다.

## Vercel 배포

GitHub 저장소를 Vercel에 연결한 뒤 아래 환경 변수를 Preview/Production에 각각 등록합니다.

```text
VITE_SUPABASE_URL
VITE_SUPABASE_PUBLISHABLE_KEY
VITE_JOB_INFO_MVP_MODE=disabled
VITE_CLOSED_BETA_MODE=disabled
VITE_OPEN_BETA_MODE=disabled
VITE_SERVICE_LAUNCH_MODE=disabled
```

빌드 명령은 `npm run build`, 출력 디렉터리는 `dist`입니다. `vercel.json`에 SPA 라우팅, 서비스 워커 캐시 제어, 기본 보안 헤더가 포함되어 있습니다.

## 서비스 런치 준비

개발 검증 환경에서만 다음 값을 설정합니다.

```text
VITE_SERVICE_LAUNCH_MODE=development
```

- 기존 수동 소개, 계약 확인, 근무 결과를 `service_cases`의 현재 단계와 변경 이력으로 연결
- 고용주 의견은 덮어쓰지 않고 별도 이력으로 누적
- 정식 수수료 금액·정책 버전·확인일이 모두 설정되어야 실제 결제 완료 기록 가능
- 사업 등록, 계약 확인, 결제 제공자와 서버 웹훅 검증까지 모두 통과해야 `paid` 기록 가능
- 근로계약은 고용주와 근로자가 직접 체결하며 업무 지시와 임금 지급도 고용주가 수행
- 플랫폼의 임금 보관·지급 기능은 포함하지 않음

현재 정식 수수료는 제공되지 않아 19,000원을 확정 가격으로 사용하지 않습니다. 근로자
업무정보 자동화와 AI 맞춤 매칭은 실제 근무 결과가 충분히 쌓인 뒤의 고도화 계획으로만
유지하며, 충분성 기준이나 모델 성능 기준은 아직 설정하지 않았습니다.

## 가상 레코드

`demo_employers` 30건과 `demo_workers` 200건을 실제 회원·소개 데이터와 분리해 저장합니다.
모든 행에는 `시연용 가상 데이터`가 고정되어 있고 이메일·전화번호 같은 가짜 개인정보는
포함하지 않습니다. 이 레코드는 실제 회원, 매칭, 재이용, 결제 또는 운영 성과 집계에
포함되지 않습니다.

시제품 참여 목표는 고용주 30명·근로자 200명입니다. 가상 레코드는 화면 설명용이며,
목표 달성이나 실제 이용 실적의 근거로 사용하지 않습니다. 실제 실적은 기록이 없으면
`미집계`로 표시합니다.

## 중요 운영 원칙

AI 점수는 채용을 자동 결정하지 않으며, 설명 가능한 추천 근거만 제공합니다. 국적·비자 유형 같은 민감 정보는 법적 고용 가능성 확인 범위에서만 사용하고 점수 산정에는 사용하지 않는 것을 권장합니다. 실제 운영 전 노무·출입국·개인정보 전문가의 검토를 받으세요.

## 2026-09-16 사업 확장 화면 (최신 범위)

이 절은 이전 PRD/디자인 초안의 확정되지 않은 데이터 수·점수·비자·포인트 가정보다 우선합니다.

| 화면 | 실제 동작 | 시연·예정 범위 |
| --- | --- | --- |
| `#worker-information` | 로그인 근로자의 본인 업무정보·동의 이력·운영 근무 결과 읽기 전용 조회 | 고용주에게는 별도 시연 DB의 가상 근로자 요약. 실제 정보 제공·자동화는 개발 예정 |
| `#matching` | 본인/소유 공고의 허용된 운영 기록을 조건별로 표시 | 시연 레코드 선택·비교. AI 미연결, 점수·순위·거리 계산 없음 |
| `#visa` | 안내 및 화면 이동 | ‘외국인 근로자 단기 비자 지원 — 검토 예정’. 기존 유형 입력·파트너 연결 시연 제거 |
| `#points-policy` | 안내 및 화면 이동 | ‘현금 인출 가능한 플랫폼 포인트 — 검토 예정’. 잔액·현금 가치·출금 UI 없음 |

실제 저장 정보와 시연 탭을 구분하며, 조회 오류를 미등록이나 가상 데이터로 대체하지 않습니다.
DB 조회는 `src/expansion-data.js`, 화면은 `src/expansion.js`에 분리했습니다. 새 저장 기능·회원 공유 권한·DB 마이그레이션은 추가하지 않았습니다.

### 실제 고용주 제공 전 필요한 결정

- 유료직업소개사업 등록 완료 확인 및 운영 승인
- 업무정보 제3자 제공 동의 문안, 수신 고용주, 제공 항목, 목적, 보유기간, 철회 방법
- 기존 매칭 접근 권한을 위 동의/범위와 결합하는 서버 권한 설계 및 별도 보안 검증
- 거리 계산 방식·근거리 기준, 근무 결과 정의 및 데이터 충분성/모델 검증 기준
- 비자 지원 범위·운영 방식, 포인트 적립 기준·환산 비율·출금 조건

현 상태에서는 기존 `matches` 관계를 고용주 제공 동의로 인정하지 않으며, 확장 화면은 고용주 권한으로 다른 근로자를 조회하지 않습니다. 개인 연락처·국적·비자·좌표·기존 점수 컬럼은 업무정보 요약 조회에서 제외합니다.

### 메뉴 이동과 검증

휴대폰/태블릿(1,000px 이하)은 메뉴를 누르면 애니메이션 없이 즉시 이동합니다. PC의 기존 옆 이동은 유지합니다. 사이트 내부 메뉴는 `replaceState`로 주소만 변경하여 뒤로/앞으로 기록을 누적하지 않습니다.
화면 너비가 바뀌면 현재 주소의 페이지를 다시 정렬하며, 키보드로 인한 높이 변경만으로는 입력 화면을 이동하지 않습니다. 업데이트 전에 쌓인 브라우저 기록은 삭제하지 않습니다.

`npm test`로 빈 값·오류 구분, 역할별 조회 범위, 점수 미생성, 검토 예정 안내 및 시연 선택을 검사합니다. `npm run check`, `npm run build`로 구문/빌드 검증을 실행합니다.

### 이번 변경의 검증 결과와 한계

- 자동 테스트 12개 통과, 구문 검사 및 Vite 프로덕션 빌드 통과.
- 실제 Supabase 연결 및 RLS 적용을 확인. 근로자/고용주 역할의 읽기 전용 트랜잭션에서 각 본인 프로필 1건만 조회됨을 확인했고, 검증 트랜잭션은 롤백했습니다.

### 위치정보 처리

사용자가 요청한 90일 보관을 적용했습니다. 동의 내용·버전·시점·만료 시점을 저장합니다.
선택적 동의이며 가입·로그인과 분리됩니다. 정확한 좌표는 본인 조회 외 회원 API에 공개하지 않습니다.
동의 철회는 좌표를 즉시 삭제하고 거리 결과를 무효화합니다. 기간 만료 즉시 조회/공유를 차단하고
`geugot-purge-expired-commute-locations` 작업이 1분마다 만료 좌표를 운영 DB에서 삭제합니다.
작업 등록뿐 아니라 실제 `succeeded` 실행 이력을 확인했습니다.
운영 DB 삭제 범위이며 별도 백업의 보유기간·국외 이전·사업자/담당자 고지는 최종 개인정보 처리방침 검토가 필요합니다.
자동 위치 센서 수집은 추가하지 않았습니다. 비로그인 상태에서는 별도 기기 내 계산기만 이용하며 좌표를 전송하지 않습니다.
